──泛化的关键：唯一的仓相关物 = 一份描述符───────────────────────────────────────────────────────────────────────────────

   ─────────────┌────────────────仓相关（每个仓一份，多为自动派生）─────────────────────────────────────────────────────
                │  Repo Descriptor: 仓名/URL/code globs/backlog映射
                ▼
  [任意仓 R] ──► 一套框架实现（仓无关，写一次服务所有仓）──► [标准 Wiki for R]

  换一个仓 = 写一份新描述符，不改一行框架代码。这是验收框架"是否真泛化"的硬标准。

  六层架构（蓝图全画，前三层可落地）

  ┌────────────────────┬────────────────────────────────────────────────────────────┬──────────────────┐
  │         层         │                       职责（仓无关）                       │       状态       │
  ├────────────────────┼────────────────────────────────────────────────────────────┼──────────────────┤
  │ L1 来源发现        │ 给定仓名 →按规则发现 code + backlog 全部来源              │ ✅ 可落地        │
  ├────────────────────┼────────────────────────────────────────────────────────────┼──────────────────┤
  │ L2 编译            │ 对每个来源跑 knowledge-core（freeze→normalize→claim→wiki│ ✅ 复用现有      │
  ├────────────────────┼────────────────────────────────────────────────────────────┼──────────────────┤
  │ L3 标准产出        │ 合并成统一骨架 Wiki，进 output/<repo>/，走 PR              │ ✅ 可落地        │
  ├────────────────────┼────────────────────────────────────────────────────────────┼──────────────────┤
  │ L4 AI消费(MCP)     │ MCP server 暴露 query_knowledge(repo, q)→带引用答案       │ 🔷 蓝图+接口契约 │
  ├────────────────────┼────────────────────────────────────────────────────────────┼──────────────────┤
  │ L5 local-debug验证 │ 注入知识 vs 裸跑，量 token+质量                            │ 🔷 蓝图+协议     │
  ├────────────────────┼────────────────────────────────────────────────────────────┼──────────────────┤

  L4-L6 只碰我方的产物和 local clone，永不改线上 workflow（守你的红线）。

  五个仓无关契约（框架的真正骨架）

  1. Repo Descriptor（输入契约） —唯一仓相关配置，字段：canonical_url、code include/exclude globs、backlog
  映射键（project 标签名 / service 名）。大部分可从 backlog 自动派生。
  2. Backlog 发现规则（发现契约） —一套规则映射 仓 →{issue_docs/*, changelogs/*, services/R.yaml}。对所有仓通用。
  3. 标准 Wiki 契约（产出契约） —每个仓同一骨架：整体概述 / 架构与组件(What) / 关键决策与边界(Why) / 部署与运维(How) /
  已知问题与复盘(坑) / 来源核验。knowledge-core 已有 wiki_validation 门禁，扩展章节校验即可。
  4. MCP 接口（消费契约） —仓无关工具签名。蓝图，先定接口不实现。
  5. 验证协议（验证契约） —仓无关的"带知识/裸跑"对照测量法。forum-reply-robot + issue 1611 是第一个实例。

  落地目录（扩展 openKnowledgeBase）

  knowledgeManagement/
    knowledge-core/            # 现有引擎，不动
    compile-framework/         # 新增：仓无关框架层
      descriptors/             # 每仓一份 yaml（仓相关的唯一处）
      discovery.py             # L1 发现规则（仓无关）
      orchestrate.py           # L2 编排 knowledge-core（仓无关）

      interfaces/              # L4-L6 接口契约（蓝图，仅签名+文档）
  output/<repo>/               # 标准 Wiki 产出，git+PR
