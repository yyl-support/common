# 数据库访问指南

适用于 forum-reply-robot 工程的 PostgreSQL 存储。工程停机不影响数据库访问,数据库作为独立服务运行。

## 连接参数

优先从 `config/config.yaml` 的 `database` 段读,回退 `config.yaml.local-bak` / `config.yaml.startup-bak`。

**本地开发机(当前默认)**

| 项 | 值 |
|---|---|
| host | 127.0.0.1 |
| port | 5432 |
| database | openeuler_forumrobot |
| user | postgres |
| password | gorden |
| sslmode | disable |

**生产/远程**

| 项 | 值 |
|---|---|
| host | 10.0.0.201 |
| port | 5432 |
| database | openeuler_forumrobot |
| user | discourse |
| password | 见 `config/config.yaml.startup-bak` |

生产地址从本机直连会超时,需要 SSH 隧道或已接入内网。

## 访问方式

### 1) 工程自带 CLI(推荐)

```bash
# 列所有表 + 行数
.venv/Scripts/python.exe scripts/db_shell.py tables

# 看某张表前 10 行
.venv/Scripts/python.exe scripts/db_shell.py show forum_topics --limit 10
.venv/Scripts/python.exe scripts/db_shell.py show eval_retrieval_runs --limit 20

# 跑任意 SQL
.venv/Scripts/python.exe scripts/db_shell.py sql "SELECT id, title FROM forum_topics ORDER BY id DESC LIMIT 5"

# 看某次评测的汇总
.venv/Scripts/python.exe scripts/db_shell.py eval-report --run-tag baseline-2026-05-11
```

环境变量覆盖:`DB_URL=postgresql://user:pass@host:port/db`。

### 2) 命令行 psql

```bash
# 本地
PGPASSWORD=gorden psql -h 127.0.0.1 -p 5432 -U postgres -d openeuler_forumrobot

# psql 内部常用
\dt                     -- 列所有表
\d forum_topics         -- 表结构
\x                      -- 切换扩展显示(大字段列友好)
```

### 3) GUI 客户端

DBeaver / pgAdmin / DataGrip 新建 PostgreSQL 连接,填上面连接参数即可。评测相关表在 `public` schema:
- `eval_query_set`
- `eval_retrieval_runs`
- `eval_metric_scores`

### 4) Python 代码

```python
import psycopg2
from psycopg2.extras import RealDictCursor

conn = psycopg2.connect(
    host="127.0.0.1", port=5432,
    database="openeuler_forumrobot",
    user="postgres", password="gorden",
    sslmode="disable",
)
with conn.cursor(cursor_factory=RealDictCursor) as cur:
    cur.execute("SELECT id, title FROM forum_topics LIMIT 5")
    for row in cur.fetchall():
        print(row)
```

## 表速览

### 业务主表(来自 CSV 迁移)

| 表 | 说明 |
|---|---|
| `forum_topics` | 论坛主贴原始数据(未处理) |
| `processed_forum_topics` | 已生成 LLM 回复的帖子 |
| `pre_audit_topics` / `pre_audit_processed_topics` | 预审(SchemaValidation)相关 |
| `forum_search_results` | doc-search 搜索结果 |
| `forum_retrieval_results` | LightRAG 检索出的 KG+DC 上下文 |
| `consume_tokens_topic` | 每个 topic 的 token 消耗明细 |
| `schema_debug_logs` | SchemaValidation 调试日志 |

### 评测新增表(本次引入)

| 表 | 主键 | 说明 |
|---|---|---|
| `eval_query_set` | `query_id` | 评测查询集,`expected_output` 可选 |
| `eval_retrieval_runs` | `(query_id, backend, run_tag)` | 每次评测跑的检索结果 + 延迟 + LLM 答案 |
| `eval_metric_scores` | `(run_id, metric_name)` | 每个指标分数 + 理由 |

## 常用查询

**查某 topic_id 的完整链路**
```sql
SELECT
    t.id, t.title, left(t.user_question, 80) AS question_preview,
    left(p.llm_answer, 80) AS answer_preview,
    (SELECT length(related_docs) FROM forum_retrieval_results WHERE topic_id=t.id
     ORDER BY created_at DESC LIMIT 1) AS retrieval_bytes,
    (SELECT total_tokens FROM consume_tokens_topic WHERE topic_id=t.id
     ORDER BY created_at DESC LIMIT 1) AS tokens
FROM forum_topics t
LEFT JOIN processed_forum_topics p ON p.id = t.id
WHERE t.id = 29510;
```

**LLM 回复失败的帖子**
```sql
SELECT id, title, left(llm_answer, 120) AS llm_answer
FROM processed_forum_topics
WHERE llm_answer ILIKE '处理失败%' OR llm_answer IS NULL OR llm_answer = ''
ORDER BY id DESC;
```

**按 run_tag 汇总指标均值(评测报表)**
```sql
SELECT r.backend, s.metric_name,
       COUNT(s.score)         AS n,
       ROUND(AVG(s.score)::numeric, 3) AS mean,
       SUM(CASE WHEN s.error IS NOT NULL THEN 1 ELSE 0 END) AS errors
FROM eval_retrieval_runs r
JOIN eval_metric_scores s ON s.run_id = r.id
WHERE r.run_tag = 'baseline-2026-05-11'
GROUP BY r.backend, s.metric_name
ORDER BY r.backend, s.metric_name;
```

**两后端直接对比(需要同一 query_id 在两个 backend 下都跑过)**
```sql
SELECT q.query_id,
       MAX(CASE WHEN r.backend='lightrag' THEN s.score END) AS lightrag,
       MAX(CASE WHEN r.backend='pgvector' THEN s.score END) AS pgvector
FROM eval_query_set q
JOIN eval_retrieval_runs r ON r.query_id = q.query_id
JOIN eval_metric_scores s ON s.run_id = r.id
WHERE s.metric_name = 'faithfulness'
  AND r.run_tag IN ('baseline-2026-05-11','pgvector-2026-05-11')
GROUP BY q.query_id ORDER BY q.query_id;
```

**LightRAG 检索延迟分布**
```sql
SELECT run_tag,
       MIN(retrieval_latency_ms) AS min_ms,
       AVG(retrieval_latency_ms)::INTEGER AS mean_ms,
       percentile_cont(0.5)  WITHIN GROUP (ORDER BY retrieval_latency_ms)::INTEGER AS p50_ms,
       percentile_cont(0.95) WITHIN GROUP (ORDER BY retrieval_latency_ms)::INTEGER AS p95_ms,
       MAX(retrieval_latency_ms) AS max_ms
FROM eval_retrieval_runs
WHERE backend = 'lightrag'
GROUP BY run_tag ORDER BY run_tag;
```

## 备份与恢复

```bash
# 备份(单库)
pg_dump -h 127.0.0.1 -U postgres -d openeuler_forumrobot -F c -f forum_backup.dump

# 恢复
pg_restore -h 127.0.0.1 -U postgres -d openeuler_forumrobot_new forum_backup.dump
```

## 注意事项

- `config.yaml` 会在主程序启动后被 `delete_config_file` 删除,工程运行时无法读到它。开发评测时手工从 `.local-bak` 复制一份即可。
- `related_docs` / `retrieval_context` 字段常达数万字符,`SELECT *` 时请用 `\x` 扩展显示或 `LEFT(col, N)` 裁剪。
- 所有评测数据表用 `ON CONFLICT DO UPDATE` 上覆盖,重跑同一 `run_tag` 会覆盖旧结果,不会重复堆积。想保留历史就换新的 `run_tag`。
