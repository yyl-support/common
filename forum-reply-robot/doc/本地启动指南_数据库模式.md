# forum-reply-robot 本地启动指南（数据库模式）

适用环境：**Windows Server 2019**（其他 Windows 版本同理），**Python 3.11**（64-bit），**本机 PostgreSQL 16**。

> 本指南与 `本地启动指南.md`（CSV 模式）平行。区别：把 `storage.backend` 从 `'csv'` 切到 `'database'`，数据持久化指向本机 PG 实例 `127.0.0.1:5432/openeuler_forumrobot`。其余前置步骤（Python 3.11 venv、`netifaces-plus`、`SchemaFiles` 克隆、`web-server.discourse → discourse.test.osinfra.cn` 等）全部沿用 CSV 版指南，不再重复。

## 一、本次切换到数据库模式所做的改动

### 1.1 配置改动

在 `本地启动指南.md` 给出的配置基础上，再改两处：

| 位置 | 字段 | 改动前 | 改动后 |
|------|------|--------|--------|
| `config/config.yaml` L24-25 | `storage.backend` | `'csv'` | `'database'` |
| `config/config.yaml` L95-101 | `database.*` | 指向生产 `10.0.0.201` / `discourse` | 指向本机 `127.0.0.1` / `postgres` / 本地密码 |

示例（本机 PG 超级用户 `postgres` / 密码 `gorden` / 库 `openeuler_forumrobot`）：

```yaml
storage:
  backend: 'database'

database:
  host: '127.0.0.1'
  port: '5432'
  database: 'openeuler_forumrobot'
  user: 'postgres'
  password: 'gorden'
  sslmode: 'disable'
```

> `main.py:234` 的 `delete_config_file()` 启动后会删除 `config/config.yaml`，本地库密码会在磁盘上短暂出现。下面 1.5 节给出一份独立的"本地版备份"方案。

### 1.2 数据库初始化

PG 本机已安装。需要**一次性**执行：

1. 创建目标数据库 `openeuler_forumrobot`（如不存在）。
2. 由 `DataProcessor.create_tables()` 创建 7+1 张业务表（多出来的 1 张是 `schema_debug_logs`）。
3. 给 `consume_tokens_topic.topic_id` 加唯一索引 —— `DataProcessor.create_tables()` 没有声明该约束，但 `migrate_csv_to_db.py` 依赖 `ON CONFLICT (topic_id) DO UPDATE`，没有唯一索引会报 `there is no unique or exclusion constraint matching the ON CONFLICT specification`。

### 1.3 `migrate_csv_to_db.py` 代码修复

原脚本在 `forum_topics` 表和 `consume_tokens_topic` 表都使用 `execute_values` + `ON CONFLICT (主键) DO UPDATE`。如果同一批 CSV 里同一个 `id` / `topic_id` 出现多次（历史抓取留下的重复行），一次 `INSERT ... VALUES ...` 会让同一行被 `ON CONFLICT DO UPDATE` 命中两次，PostgreSQL 抛：

```
psycopg2.errors.CardinalityViolation:
ON CONFLICT DO UPDATE command cannot affect row a second time
```

修复方式：在构造好 `rows` 之后、`execute_values` 之前，用字典按主键去重，保留最后一条（CSV 是追加写，末尾即最新状态）。`forum_topics` 和 `consume_tokens_topic` 两处都加了同样的去重逻辑，并打印 `存在 N 条重复 xxx，保留最后一条` 方便核账。

其他几张表（`processed_forum_topics`、`pre_audit_*`、`forum_search_results`、`forum_retrieval_results`）要么主键是 `SERIAL` 自增、要么迁移时不走 `ON CONFLICT`，不受影响。

### 1.4 配置备份策略

| 文件 | 角色 |
|------|------|
| `config/config.yaml.startup-bak` | 生产库凭据（host=10.0.0.201 / user=discourse） |
| `config/config.yaml.local-bak` | **本机 PG 凭据（本指南新增）** |

`main.py` 启动后会删除 `config/config.yaml`。本地模式下，重启前从 `config.yaml.local-bak` 恢复，而不是 `.startup-bak`。

### 1.5 一次迁移后的初始行数（参考）

从 `data/forum_data/*.csv` 迁过来的基线行数（用于之后回归比对）：

| 表 | 行数 |
|----|-----:|
| forum_topics | 15 |
| processed_forum_topics | 11 |
| pre_audit_topics | 59 |
| pre_audit_processed_topics | 22 |

## 二、首次切换到数据库模式的完整步骤

> 假设：CSV 模式的环境（venv、`netifaces-plus`、`SchemaFiles`、`config/config.yaml.startup-bak` 等）已按 `本地启动指南.md` 搭好。若未搭，请先走那份指南的 Step 1–5。
>
> 本机 PostgreSQL 已安装，`psql.exe` 在 `D:\user\data\bin\psql.exe`，监听 `127.0.0.1:5432`。下文示例假设超级用户是 `postgres`，密码是 `gorden` —— 按你的实际环境替换。

### Step 1. 确认本地 PG 可连

```bash
PGPASSWORD=gorden "/d/user/data/bin/psql.exe" -h 127.0.0.1 -U postgres -d postgres -c "SELECT version();"
```

预期看到 `PostgreSQL 16.x ...`。

### Step 2. 创建目标数据库

```bash
PGPASSWORD=gorden "/d/user/data/bin/psql.exe" -h 127.0.0.1 -U postgres -d postgres \
  -c "CREATE DATABASE openeuler_forumrobot WITH ENCODING 'UTF8';"
```

> 已存在时会报 `database "openeuler_forumrobot" already exists`，忽略即可。

### Step 3. 生成本地版 `config/config.yaml`

从"CSV 版启动备份"拷一份，然后改 `storage.backend` 和 `database.*`：

```bash
cp config/config.yaml.startup-bak config/config.yaml
```

用编辑器把下列两段改成本机值：

```yaml
storage:
  backend: 'database'

database:
  host: '127.0.0.1'
  port: '5432'
  database: 'openeuler_forumrobot'
  user: 'postgres'
  password: 'gorden'
  sslmode: 'disable'
```

再存一份独立备份，方便下次重启：

```bash
cp config/config.yaml config/config.yaml.local-bak
```

### Step 4. 创建业务表

直接调用 `DataProcessor.create_tables()`，与 `main.py` 启动时走的是同一条路径：

```bash
cd /d/user/code/forum-reply-robot
PYTHONPATH=. PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe -c "
from src.utils import load_config
from src.ForumBot.data_processor import DataProcessor
cfg = load_config()
DataProcessor(cfg).create_tables()
"
```

预期日志：`数据库表创建成功`。

校验表是否齐全：

```bash
PGPASSWORD=gorden "/d/user/data/bin/psql.exe" -h 127.0.0.1 -U postgres \
  -d openeuler_forumrobot -c "\dt"
```

应出现 8 张表：`forum_topics`, `processed_forum_topics`, `pre_audit_topics`, `pre_audit_processed_topics`, `forum_search_results`, `forum_retrieval_results`, `consume_tokens_topic`, `schema_debug_logs`。

### Step 5. 给 `consume_tokens_topic.topic_id` 加唯一索引

```bash
PGPASSWORD=gorden "/d/user/data/bin/psql.exe" -h 127.0.0.1 -U postgres \
  -d openeuler_forumrobot \
  -c "CREATE UNIQUE INDEX IF NOT EXISTS uq_consume_tokens_topic_topic_id ON consume_tokens_topic (topic_id);"
```

### Step 6. 执行 CSV → DB 迁移

```bash
cd /d/user/code/forum-reply-robot
PYTHONPATH=. PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe migrate_csv_to_db.py
```

关键日志：


> 迁移脚本每张表都会先 `TRUNCATE` 再写入，结果是"CSV 的最终态快照"，幂等。若 CSV 里同主键多次出现，会看到 `存在 N 条重复 ...，保留最后一条` 的提示。

### Step 7. 启动主程序

## 四、为什么这样改

| 点 | 原因 |
|----|------|
| `storage.backend: database` | 走 `DataProcessor` 的数据库分支（`topic_manager_db` / `pre_audit_manager_db` 等），状态从 CSV 切到 PG，可多进程/多实例并发读写 |
| `host: 127.0.0.1` / `user: postgres` | 原配置 `10.0.0.201 / discourse` 是生产库，开发机无权访问；本机装了 PG 后用本地超级用户最省事 |
| 建目标库 + `create_tables()` | `DataProcessor` 在 database 模式下会连已指定的库，但不会自动建库；建表由它内部 DDL 完成，不需要手写 SQL |
| 给 `consume_tokens_topic.topic_id` 加唯一索引 | `DataProcessor.create_tables()` 的 DDL 只在 `id` 上建主键，没给 `topic_id` 加唯一约束；`migrate_csv_to_db.py` 和运行期的 `upsert_token_usage` 都依赖 `ON CONFLICT (topic_id)`，缺少唯一索引会直接抛 `no unique or exclusion constraint matching the ON CONFLICT specification` |
| `migrate_csv_to_db.py` 加主键去重 | `execute_values` 批量插入里同一主键出现两次，`ON CONFLICT DO UPDATE` 就会命中同一行两次，触发 `CardinalityViolation`。CSV 是追加写，重复是历史痕迹，保留最后一条等价于"最终态" |
| `config.yaml.local-bak` | 与 `.startup-bak`（生产凭据）区分开；重启前恢复这份即可，不会误用生产库 |

## 五、常见问题排查

### Q1. 启动报 `FATAL: password authentication failed for user "postgres"`
`config/config.yaml` 里 `database.password` 和本机 PG 的 `postgres` 密码对不上。用 `psql` 直接验证一下密码，或在 `pg_hba.conf` 把 `127.0.0.1` 的认证方式临时改为 `trust` 试错。

### Q2. 启动报 `database "openeuler_forumrobot" does not exist`
跳过了 Step 2。回头执行 `CREATE DATABASE openeuler_forumrobot ...`。

### Q3. 运行期报 `there is no unique or exclusion constraint matching the ON CONFLICT specification`
`consume_tokens_topic.topic_id` 缺唯一索引。执行 Step 5 里的 `CREATE UNIQUE INDEX`。

### Q4. 迁移报 `ON CONFLICT DO UPDATE command cannot affect row a second time`
对应的 CSV 里同一个 `id` / `topic_id` 出现多次。当前 `migrate_csv_to_db.py` 已做去重，若仍报错说明你拿的是没改过的旧版脚本；检查 `migrate_topics_table` / `migrate_token_usage_table` 里是否有 `deduped = {}` 的去重块。

### Q5. 启动后 `forum_topics` 只有新帖子，没有历史迁入的 15 条
可能 `main.py` 再次跑了一次 "初始数据迁入"。当前代码路径下，`DataProcessor` 只是 `create_tables()`，不会动业务数据；如果行数意外丢失，先确认不是谁手动跑了 `TRUNCATE` 或重跑了 `migrate_csv_to_db.py`（脚本每张表先清空再插入）。

### Q6. 想临时切回 CSV 模式对比
`cp config/config.yaml.startup-bak config/config.yaml`（生产库凭据那份，但 `storage.backend` 还是 `csv`，用来本地跑不会真连 10.0.0.201）或手动把 `storage.backend` 改回 `'csv'`。两套备份分开后，切换很便宜。
