# forum-reply-robot 本地启动指南

适用环境:**Windows Server 2019**(其他 Windows 版本同理),**Python 3.11**(64-bit)。

> 项目原本只在 Docker (Linux + Python 3.9) 下启动。本指南记录在 Windows 主机上**本地直接运行** `main.py` 所需的全部改动与步骤。
> 数据持久化策略:**CSV 模式**(`storage.backend: 'csv'`),不依赖 PostgreSQL。

---

## 一、本次为启动工程所做的改动清单

### 1.1 配置文件改动

修改 `config/config.yaml`,把容器内部域名 `web-server.discourse:8080` 改为公网可达的 `discourse.test.osinfra.cn`。共 **3 处**:

| 行号 | 字段 | 改动前 | 改动后 |
|------|------|--------|--------|
| 55 | `posts.base_url` | `https://web-server.discourse:8080` | `https://discourse.test.osinfra.cn` |
| 84 | `forum.base_url` | `https://web-server.discourse:8080` | `https://discourse.test.osinfra.cn` |
| 113 | `image_processing.base_url` | `https://web-server.discourse:8080` | `https://discourse.test.osinfra.cn` |

> 原因:容器内可通过 docker network 解析 `web-server.discourse`,Windows 主机上无法解析此域名,会触发 `getaddrinfo failed`。

> 备份文件:启动过程中保留了 `config/config.yaml.startup-bak`(完整修改后内容),`main.py` 启动后会自动删除 `config.yaml`(脱敏机制),下次启动前需从备份恢复。

### 1.2 环境改动

| 项 | 内容 |
|----|------|
| 安装 Python 3.11 | 因 `netifaces` 0.11.0 在 PyPI 上**没有 Python 3.11+ 之外的预编译 wheel**,3.13 / 3.12 都需 MSVC 编译;3.11 可直接用 `netifaces-plus` 走预编译 wheel。 |
| 创建 venv | 项目根下 `.venv`(`py -3.11 -m venv .venv`)。 |
| 安装 `requirements.txt` | 在 venv 内执行,Win 上会跳过 `netifaces`(其 marker 为 `sys_platform != 'win32'`)。 |
| **额外**安装 `netifaces-plus` | `netifaces` 的官方 fork,API 完全兼容(`import netifaces` 不变),提供 cp311 wheel,无需 MSVC。 |
| 克隆 `SchemaFiles` 仓库 | `main.py` 启动前会检查 `src/ForumBot/SchemaValidation/SchemaFiles/` 是否存在且非空,Dockerfile 里通过 `git clone` 拉取;本地需手动执行同样的命令。 |

### 1.3 源代码改动

为验证 `required_tag` 配置效果，对 `src/ForumBot/data_processor.py` 增加了显式日志打印（行号 171-185）:

```python
# 检查是否有任何一个所需的标签存在于帖子标签中
tag_matched = False
matched_tag = None
for required_tag in required_tags:
    if required_tag in topic_tags_str:
        tag_matched = True
        matched_tag = required_tag
        break

if not tag_matched:
    continue  # 如果不包含任何所需标签，则跳过

# 显式打印带有 required_tag 的帖子信息
logger.info(f"[REQUIRED_TAG_MATCHED] 检测到帖子包含标签 '{matched_tag}'")
logger.info(f"[REQUIRED_TAG_MATCHED] 帖子ID: {topic.get('id')}, 标题: {topic.get('title')}, 标签: {topic_tags_str}")
```

当帖子包含配置中的 `required_tag`（如 `'提问求助'` 或 `'qa-提问求助'`）时，日志会显式打印:
```
[REQUIRED_TAG_MATCHED] 检测到帖子包含标签 '提问求助'
[REQUIRED_TAG_MATCHED] 帖子ID: 12345, 标题: 示例标题, 标签: 提问求助,其他标签
```

### 1.4 配置参数调整

修改 `topic_cutoff_date` 截止日期参数:

| 文件 | 行号 | 改动前 | 改动后 |
|------|------|--------|--------|
| `config/config.yaml.startup-bak` | 37 | `'2026-04-09'` | `'2026-05-06'` |
| `config/config.txt` | 27 | `'2026-04-09'` | `'2026-05-06'` |

> 该参数控制只处理创建时间在该日期之后的帖子。

### 1.5 API 速率限制优化

解决 "HTTP 429 Too Many Requests" 问题，优化 API 请求间隔和错误处理:

| 文件 | 参数 | 改动前 | 改动后 | 说明 |
|------|------|--------|--------|------|
| `config/config.yaml.startup-bak` | `forum.request_delay` | `0.1` | `0.5` | Discourse 论坛 API |
| `config/config.yaml.startup-bak` | `gitcode.request_delay` | `1.5` | `2.0` | GitCode API (50次/分钟限制) |
| `config/config.txt` | `forum.request_delay` | `0.1` | `0.5` | Discourse 论坛 API |
| `config/config.txt` | `gitcode.request_delay` | `1.5` | `2.0` | GitCode API |

源代码修改 (`src/update_lightrag/gitcode_client.py`):
- `get_commits_since()` 方法（行 54-114）：添加 429 状态码重试逻辑
- `get_file_content()` 方法（行 28-56）：添加 429 状态码重试逻辑
- `get_compare_files()` 方法（行 115-174）：已存在 429 处理，保留不变

重试机制：遇到 429 状态码时，等待 30 秒后重试，最多重试 2 次。

## 二、首次启动 / 重新搭建环境的完整步骤

> 假设当前目录为项目根 `D:\user\code\forum-reply-robot`。所有命令在 Git Bash 或 PowerShell 中执行均可,本指南给出 Git Bash 命令(项目仓库的 `git status` 表明你已经在用 bash shell)。

### Step 1. 安装 Python 3.11

从 https://www.python.org/downloads/release/python-3119/ 下载 64-bit 安装包,**勾选 "Add python.exe to PATH"** 安装。

验证:
```bash
py -0
# 期望输出包含: -V:3.11   Python 3.11 (64-bit)
```

### Step 2. 创建并激活虚拟环境

```bash
cd /d/user/code/forum-reply-robot
py -3.11 -m venv .venv
.venv/Scripts/python.exe --version   # 应该输出 Python 3.11.x
```

### Step 3. 安装项目依赖

```bash
.venv/Scripts/python.exe -m pip install --upgrade pip
.venv/Scripts/python.exe -m pip install -r requirements.txt
```

### Step 4. 安装 netifaces 替代实现

```bash
.venv/Scripts/python.exe -m pip install netifaces-plus
```

> `netifaces-plus` 是 `netifaces` 的官方维护 fork,导入名仍为 `netifaces`,API 兼容,无需修改源代码。

验证:
```bash
.venv/Scripts/python.exe -c "import netifaces; print(netifaces.interfaces()[:3])"
```

### Step 5. 克隆 SchemaFiles 仓库

```bash
git clone https://gitcode.com/Richardli25/Redfish_SchemaFile.git \
  src/ForumBot/SchemaValidation/SchemaFiles
rm -rf src/ForumBot/SchemaValidation/SchemaFiles/.git
```

> 与 Dockerfile 第 79–82 行的逻辑一致。约 7900 个文件,首次克隆需要 1–2 分钟。

### Step 6. 准备配置文件

如果 `config/config.yaml` 不存在(被上一次启动自动删除了),从备份恢复:
```bash
cp config/config.yaml.startup-bak config/config.yaml
```

确认 3 处域名替换已生效:
```bash
grep -n "discourse.test.osinfra.cn\|web-server.discourse" config/config.yaml
```
应当看到 `discourse.test.osinfra.cn` 出现在 `posts`、`forum`、`image_processing` 三个 `base_url` 处,**没有**任何 `web-server.discourse`。

> 持久化策略已设为 CSV,无需改动:
> ```yaml
> storage:
>   backend: 'csv'
> ```

### Step 7. 启动主程序

```bash
PYTHONPATH=. PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe main.py
```

## 四、为什么需要这些改动

| 改动 | 根本原因 |
|------|----------|
| 域名 `web-server.discourse` → `discourse.test.osinfra.cn` | 前者是容器内服务名,只能在 docker network 内解析;主机直接运行时 DNS 解析失败 |
| Python 3.11(而非 3.13/3.12) | `netifaces` 0.11.0 PyPI wheel 只覆盖到 cp310;3.11 上可用 `netifaces-plus` 的 cp311 wheel,3.12+ 暂无现成 wheel,需 MSVC 编译 |
| 安装 `netifaces-plus` | `requirements.txt` 中 `netifaces` 的 marker `sys_platform != 'win32'` 在 Windows 上跳过,但 `main.py:8` 顶层 `import netifaces` 仍要求该模块存在;`netifaces-plus` 提供同名导入 |
| 手动 `git clone` SchemaFiles | Dockerfile 在镜像构建期克隆;本地启动跳过了 Docker 流程,需手动补 |
| CSV 持久化 | `database` 配置指向 `10.0.0.201`,主机无法访问;`storage.backend: 'csv'` 让 `data_processor.create_tables()` 直接 return,跳过 DB |

## 六、常见问题排查

### Q1. 启动报 `ModuleNotFoundError: No module named 'netifaces'`
未装 `netifaces-plus`。重新执行 Step 4。

### Q2. 启动报 `SchemaFiles 目录不存在` 或 `SchemaFiles 目录为空`
未克隆 SchemaFiles。重新执行 Step 5。

### Q3. 论坛 API 返回 `HTTP 429 Too Many Requests`
Discourse 触发限流。下一轮 (`monitor.check_interval` 秒后) 会重试。
已将配置中的 `request_delay` 参数优化:
- `forum.request_delay`: 从 `0.1` 调整到 `0.5` 秒（Discourse 论坛 API）
- `gitcode.request_delay`: 从 `1.5` 调整到 `2.0` 秒（GitCode API，限制 50次/分钟）

同时在 `src/update_lightrag/gitcode_client.py` 中为所有 API 请求方法添加了 429 错误处理逻辑:
- 遇到 429 状态码时，等待 30 秒后重试，最多重试 2 次
- 适用于 `get_commits_since()`, `get_file_content()`, `get_compare_files()` 方法

### Q4. 启动报 `getaddrinfo failed: web-server.discourse`
配置里某处仍残留容器内部域名。检查:
```bash
grep -rn "web-server.discourse" config/
```

### Q5. 启动后 `config/config.yaml` 不见了
这是**正常现象** —— `main.py:234` 调用 `delete_config_file()` 删除以防敏感信息落盘。
重启前从 `config/config.yaml.startup-bak` 复制回来即可。

### Q6. `Running on http://...` 之后健康接口连不上
`main.py:38-46` 的 `get_best_private_ip()` 会从所有网卡选一个内网 IP。若机器有多张网卡,选出来的 IP 可能不是你想要的。
- 临时:看日志里实际绑定的 IP,用那个 IP 访问。
- 永久:可改 `main.py:267` 把 `host=bind_ip` 写死成 `'0.0.0.0'` 或具体 IP(本指南未做此改动)。
